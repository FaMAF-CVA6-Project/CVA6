    Compare a gem5 run with the CVA6 RTL, instruction by instruction

    FlowCompare lines up the instructions both runs commit, tells you how far gem5's cycle count is from the RTL's, and shows which instructions gain or lose the cycles.

    Or drop a MinorFlow JSON and a CVA6Flow JSON of the same program anywhere on this window.

    1. The verdict says how much faster or slower gem5 is than the RTL.
    2. The metrics set the two runs' counters side by side.
    3. The chart follows the gap across the program, in cycles or any other metric, or draws both runs.
    4. The tables name the instructions that open it.
    Click a row to mark it on the curve. ↑ and ↓ move through the rows.

    How to read FlowCompare

    FlowCompare takes one program run twice, once on gem5's MinorCPU (a MinorFlow JSON) and once on the CVA6 RTL (a CVA6Flow JSON). Both runs commit the same instructions in the same order, so FlowCompare pairs them one by one and compares when each pair commits.

    The verdict

    How many cycles gem5 needs compared with the RTL, over the main program, from the first compared instruction's commit to the last one's. Negative means gem5 is faster than the hardware. It is the same figure the calibration tables report as the cycle error. When a check is red there is no verdict, since the two runs are then not the same instructions.

    The metrics

    The counters of both runs over the same instructions. Rows marked * are counted differently by the two tools and are shown for reference, not as model error: the RTL counts every fetch it presents, wrong-path ones included, and the two D-caches count their accesses in different units.

    The chart

    Left to right is every compared instruction in commit order, from position 0, or each at its commit cycle on one run when the x axis says so. The buttons over the chart choose what it plots, one panel each over the same axis, and Shift-click shows one alone. Every count runs from the first compared instruction, so it ends at the figure the metrics card shows, and IPC is taken over the window of instructions set beside the buttons.

    Difference plots gem5 minus the RTL. For cycles the height is how many cycles gem5 is behind after that instruction, below zero when it is ahead: a slope means a stretch of code runs at a different speed, a jump means one instruction cost very different amounts on the two sides, and a flat stretch means both run in step. Relative plots the same as a percentage of the RTL, which for cycles ends at the verdict, and it starts once the RTL has counted 1% of its total, since a ratio of small counts swings wildly. Both runs draws each run on its own line. Each metric keeps one colour, on its button, its panel and its lines, and in Both runs the RTL is the grey line under gem5's. Hover to read every panel at one position, and click to open that instruction. Drag across the chart to zoom into a stretch, whose panels then scale to it, and double-click, the Whole program button or the 0 key to see everything again.

    Figures

    Screenshot, or the S key, saves the window as a PNG at three times its resolution. Export saves the chart alone as it is in view, zoom included, as a PNG, as an SVG that stays sharp in a document, or as CSV data for pgfplots, at the size chosen there, made taller when its panels would not fit. The CSV can keep at most 2,000 rows, each stretch's first, last, lowest and highest, small enough for LaTeX. View hides any part of the page or of the chart, gives the chart a title, and sets the theme, the colours, whether the lines take their metric's colour or their run's, the line width and the text size. The light theme is a calm off-white, and the colour-blind safe and greyscale palettes suit a reader who needs them. Figure mode, or the F key, leaves the chart alone on the page. The view is remembered in this browser.

    The tables

    Where the cycles go lists each instruction of the program with how many times it ran, the cycles it took on each side on average (from the previous instruction's commit to its own), and the total it adds to the gap. The rows at the top explain most of the verdict. By instruction type gathers the same by kind, for example every fld. Biggest single steps lists the single executions that moved the gap the most. Selecting a row marks its executions on the curve, brings it into a zoom that left it out, and opens the stage-by-stage timing of one of them below.

    The checks

    FlowCompare only trusts the comparison when both runs commit the same number of instructions and the instructions agree position by position. If a check turns red, the two JSONs are probably not the same program, or one of them is a slice. The Alignment menu can shift one stream against the other.

    Keys

    ? opens and closes this help, ↑ and ↓ move through the table rows, ← and → switch tables or modes when those have the focus, D, R and B choose Difference, Relative and Both runs, 0 leaves a zoom, F turns figure mode on and off, S saves a screenshot with the tooltip under the pointer, and Esc closes this help or a menu, or leaves figure mode.
